# 灵小犀前端开发交接说明

## 1. 项目定位

当前项目是纯 HTML、CSS、JavaScript 的前端展示原型，不依赖框架或构建工具。页面数据暂存在各页面脚本中的数组里，刷新页面后会恢复为演示数据；后续接入数据库时，应优先替换数据读写函数，避免改动现有 DOM 结构和视觉样式。

## 2. 目录与页面

```text
lingxi_UI/
├─ css/
│  ├─ tokens.css              # 全站颜色、字号、间距、圆角、阴影配置
│  └─ components.css          # 通用导航、按钮、卡片、表格、弹窗、表单样式
├─ docs/
│  ├─ 项目规范.md
│  └─ 开发交接说明.md
└─ pages/
   ├─ login.html              # 登录页
   ├─ index.html              # 首页工作台
   ├─ case-database.html      # 个案列表与管理
   ├─ case-detail.html        # 个案数据详情
   ├─ course-database.html    # 课程列表与管理
   └─ course-detail.html      # 课程内容编辑与预览
```

页面间使用相对链接跳转，入口为 `pages/index.html`。数据库类页面统一使用 `*-database.html`，对应详情或编辑页统一使用 `*-detail.html`。

## 3. 设计约束

- 所有主题色必须来自 `css/tokens.css`，不要在新页面中建立另一套颜色系统。
- 全站保持浅灰背景、白色卡片、低饱和蓝绿黄点缀、12–16px 圆角和轻阴影。
- 新页面应先引用 `../css/components.css`，页面特有样式可以继续写在页面内的 `<style>` 中。
- 顶部导航的三个固定入口为：工作台、个案数据库、课程中心。
- 交互元素必须有 hover、focus、按下或结果反馈；需要等待的操作应展示“处理中”状态。
- 弹窗支持取消、遮罩关闭和 Escape 键关闭；删除操作必须二次确认。
- 纯演示阶段允许使用提示条反馈，但不要保留点击后完全无变化的功能按钮。

## 4. 已实现交互

### 首页 `index.html`

- 服务流程阶段切换与摘要联动。
- 今日日程全部/待完成/已完成筛选。
- 日程完成状态双向切换。
- 新建日程、时间有效性校验和列表即时更新。
- 通知面板、全部已读、操作提示。
- 最近个案和课程中心入口跳转。

### 课程列表 `course-database.html`

- 关键词、状态、类型筛选和多种排序。
- 搜索清空、无结果提示与重置筛选。
- 新建课程表单、字数统计、模板选择和必填校验。
- 课程复制、归档/恢复、删除确认。
- 课程包文件选择与导入反馈。
- 卡片鼠标与键盘进入课程详情。

课程演示数据位于页面脚本顶部的 `courses` 数组。接后端时可保留 `renderCourses()`，将数据来源替换为接口结果。

### 课程详情 `course-detail.html`

- 页面选择、新增、复制、删除和数量同步。
- 标题、说明文字实时编辑。
- 文本、音频、视频、互动题、录音、图片组件添加与移除。
- 页面主题、标题字号、对齐方式和设备预览切换。
- 播放/暂停、重新播放、静音、进度拖动和时长设置。
- 未保存状态、保存中状态、保存完成反馈。
- 学习者视角预览和发布范围选择。
- 发布完成后状态由“草稿”变为“已发布”。

课程详情通过查询参数读取课程名称，例如：

```text
course-detail.html?id=1&name=语音意识训练课程
```

页面内容演示数据位于 `slides` 数组。当前所有保存与发布行为均为前端模拟。

## 5. 后续接入建议

1. 将登录成功行为改为鉴权完成后跳转 `index.html`。
2. 把 `courses`、`slides`、`cases` 等页面内数据迁移到统一接口层。
3. 保存课程时提交课程元数据、页面顺序、组件配置和播放设置。
4. 文件导入、音频播放和视频播放应接入真实文件地址；现有播放器负责展示交互状态，可继续复用。
5. 接口失败时保留当前内容，使用页面提示条说明失败原因，不要直接清空列表。

## 6. 提交前检查

- 页面导航是否能到达所有已存在页面。
- 搜索、筛选、排序组合后结果是否正确。
- 新增、编辑、删除后统计数字和空状态是否同步。
- 播放按钮是否在播放与暂停状态间切换，进度和时间是否同步。
- 弹窗是否可取消、点击遮罩关闭、按 Escape 关闭。
- 表单是否有必填、长度和时间范围校验。
- 手机和平板宽度下是否出现横向溢出。
- 修改 `tokens.css` 的主题色后，各页面是否同步变化。
