# 项目规范

# 需求基线

功能以甲方最新确认和群内 PDF《中文儿童叙事能力干预系统框架-流程》为准。旧 Demo 只参考设计风格，不得照搬其功能结构。详细流程与待确认边界见 `docs/需求基线与页面流程.md`。

# 设计风格

ios扁平化设计风格，适配学习困难儿童辅助网站的主题

# 色彩选用

小面积使用蓝色，务必避免商务风，色块以低‑中饱和的中性色调为主，背景白色/浅灰色，有明确的主题色。由于主题色等后期可能有多次修改，所以请将整体色调等信息以类似配置文件的形式写出或修改，便于后期修改（所有颜色通过 CSS 变量集中管理）

# 协调性

务必确保项目内所有页面的色调以及设计风格一致

# 存疑事项管理

- 项目根目录必须持续维护 `tocheck.md`，所有尚未由甲方或负责人确认的需求、规则、数据来源和技术边界均以清单形式记录。
- 开发过程中发现新的存疑项时，应先写入 `tocheck.md`，标明当前状态、已知依据和需要确认的问题，再继续完成不依赖该结论的部分。
- 获得明确结论后，应同步更新需求文档与实现，并在 `tocheck.md` 中勾选该项、补充结论和确认来源；不得直接删除历史记录。
- 以坦诚存疑为荣，以主观臆断为耻。原型中的演示数据、临时规则和降级方案必须明确标注，不得包装成已确认需求。
